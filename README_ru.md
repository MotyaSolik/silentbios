# SilentBIOS

Вайбкод хрень by Claude

Самодельный минимальный BIOS для x86 (16-бит real mode), написанный с нуля на
NASM-ассемблере. Занимает ровно 64 КБ и размещается как обычный legacy BIOS
ROM-образ — reset vector в конце файла делает `jmp` на точку входа, как на
настоящей материнской плате.

Собирался и проверялся в QEMU (`qemu-system-i386`) на каждом шаге — не
просто "компилируется", а реально гонялся с осмотром serial-вывода и
скриншотов VGA-экрана.

## Возможности

- **Вывод по COM1** (9600 8N1) — простейший, но независимый от видео канал
  диагностики.
- **VGA text mode 80×25**, настроенный полностью вручную через порты
  контроллера (Sequencer, CRTC, Graphics Controller, Attribute Controller,
  DAC-палитра) — без какой-либо видео-BIOS/option ROM. Растровый шрифт 8×16
  сгенерирован и зашит отдельным бинарником (`font.bin`, подключается через
  `incbin`).
- **POST-диагностика**: тест conventional-памяти (0–640 КБ, блоками по 64 КБ)
  и самотест контроллера клавиатуры 8042 (команда `0xAA`).
- **Интерактивное setup-меню** — стрелки/Enter/Esc, опрос клавиатуры прямым
  поллингом портов `0x60`/`0x64` (Scan Code Set 2, с фильтрацией
  make/break-кодов). Тумблеры Serial/VGA output реально встроены в вывод, а
  не просто рисуются.
- **CMOS/NVRAM** — настройки тумблеров сохраняются в CMOS (порты `0x70`/
  `0x71`) и переживают аппаратный reset, как на настоящей материнке с
  батарейкой.
- **Загрузка с диска** — чтение MBR (сектор LBA0) напрямую с первичного ATA-
  контроллера в режиме PIO (порты `0x1F0`–`0x1F7`), проверка сигнатуры
  `0x55AA` и передача управления по адресу `0000:7C00` с регистрами,
  выставленными как у настоящего BIOS (`DS=ES=SS=0`, `SP=0x7C00`,
  `DL=0x80`).
- **`int 10h`** — настоящий обработчик программного прерывания, прописанный
  в IVT. Загруженный код/ОС может просто вызывать `int 10h`, как в настоящем
  BIOS, вместо прямого доступа к видеопамяти/портам. Поддержанные функции:
  `AH=0x0E` (teletype output), `AH=0x00` (смена режима — только `0x03`),
  `AH=0x02`/`0x03` (установка/чтение позиции курсора, включая настоящий
  аппаратный курсор CRTC через порты `0x3D4`/`0x3D5`), `AH=0x0F` (чтение
  режима).

## Структура файлов

| Файл             | Назначение                                                        |
|-------------------|--------------------------------------------------------------------|
| `bios.asm`        | Исходник BIOS                                                      |
| `font.bin`        | Растровый шрифт 8×16 (256 символов × 16 байт), подключается через `incbin` |
| `sbios.bin`       | Готовый собранный образ, 65536 байт                                |
| `boot.asm` / ` boot.bin` | Тестовый загрузочный сектор (MBR) для проверки диска и `int 10h` — не часть самого BIOS, просто инструмент проверки |

## Сборка

```bash
make
```

`font.bin` должен лежать рядом с `sbios.asm` — он подключается на этапе
сборки через `incbin`, отдельно собирать/прикладывать не нужно.

## Запуск

```bash
# Без диска - POST, VGA, меню, попытка загрузки завершится "No bootable disk found"
make run_nhda

# С тестовым загрузочным сектором
make run
```

В setup-меню: стрелки вверх/вниз — навигация, Enter — переключить тумблер
или выбрать пункт, Esc — выйти и продолжить обычную последовательность
загрузки (попытку читать MBR с диска).

## Архитектурные заметки

Несколько неочевидных вещей, с которыми пришлось разобраться по ходу дела —
пригодится, если будешь читать/расширять исходник:

- **ROM — это не RAM.** `CS`/`DS` в загруженном образе указывают на сам
  ROM-образ (в реальном железе — Flash-память, доступная только на чтение).
  Все изменяемые переменные (курсор VGA, буфер под число, флаги тумблеров,
  индекс выбранного пункта меню и т.д.) поэтому вынесены в настоящую RAM —
  в свободную область сразу после IVT (`0x000`–`0x3FF`) и BDA (`0x400`–
  `0x4FF`), начиная с `0x500`, и адресуются через `ss:` (поскольку `SS`
  всегда указывает на сегмент `0x0000`).
- **Своей видео-BIOS у нас нет** — поэтому и переход в текстовый режим 80×25,
  и загрузка шрифта в Character Generator RAM (план 2 видеопамяти), и
  прошивка палитры DAC сделаны вручную, через прямое программирование
  регистров контроллера.
- **Контроллер клавиатуры отдаёт Scan Code Set 2**, а не Set 1 — это
  проверено эмпирически (не предполагалось "по документации"), и код
  обработки клавиш учитывает и это, и то, что код "отпускания" клавиши
  (`F0 xx`) оканчивается тем же байтом, что и код нажатия.
- **`int 13h` нам взять неоткуда** — раз мы сами BIOS, то работа с диском
  (`ata_read_mbr`) сделана напрямую через порты ATA-контроллера, без каких-
  либо программных прерываний.

## Известные ограничения

- Обработчик `int 10h` поддерживает `AH=0x0E`, `AH=0x00` (только режим
  `0x03`, остальные номера тихо игнорируются), `AH=0x02`/`0x03` и `AH=0x0F`.
  Прочие видео-функции тихо игнорируются.
- Загрузка с диска умеет только сектор LBA0 (MBR), без работы с разделами.
- Клавиатура читается поллингом, без IRQ/PIC — годится для setup-меню, но
  не годится для полноценной многозадачной ОС.
- Debug Key / подпись HWID — рассматривались, но осознанно не добавлены:
  проект open source, а жёсткий гейтинг фич через встроенный секрет
  технически несовместим с открытыми исходниками (секрет всё равно можно
  вытащить дизассемблером).
